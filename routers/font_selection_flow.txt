Механизм выбора шрифта: ключи и split
=====================================

В этом документе разобрана цепочка данных в двух файлах:

- routers/font_processing.py — хранит словарь стилей и обрабатывает нажатия;
- keyboards/keyboard_for_choose_fonts.py — создаёт кнопки из словаря.

1. Что хранится в словаре
------------------------

В font_processing.py создаётся словарь shrifts_dict. Каждый элемент состоит
из ключа и функции:

    "bold": fancify_text.bold

Ключ "bold" — короткое имя стиля. Значение fancify_text.bold — сама функция,
которая умеет преобразовать текст в этот стиль.

Если представить словарь как таблицу, получится так:

    ключ             значение
    "bold"           функция fancify_text.bold
    "italic"         функция fancify_text.italic
    "sans_serif"     функция fancify_text.sansSerif

Ключ нужен, чтобы позже найти нужную функцию. В словаре хранится не результат
преобразования текста, а ссылка на функцию, которую можно вызвать.

2. Как из словаря получается кнопка
-----------------------------------

Обработчик передаёт весь словарь в функцию create_choose_fonts:

    create_choose_fonts(shrifts_dict)

Внутри keyboard_for_choose_fonts.py цикл перебирает словарь:

    for key, func in shrifts_dict.items():

При каждой итерации:

- key — ключ, например "bold";
- func — соответствующая ему функция, например fancify_text.bold.

Затем функция вызывает преобразователь на тестовом слове:

    text = func("Example")

Результат становится видимой надписью на кнопке. То есть пользователь видит
не ключ "bold", а слово "Example", уже оформленное жирным шрифтом.

Одновременно кнопке задаётся callback_data:

    callback_data=f"shrift:{key}"

Для ключа "bold" эта строка получится такой:

    "shrift:bold"

Надпись кнопки и callback_data — разные вещи. Надпись видна пользователю,
а callback_data — служебная строка, которую Telegram возвращает боту после
нажатия. В неё помещают ключ, чтобы потом найти функцию в словаре.

3. Где хранится текст пользователя
---------------------------------

Когда пользователь отправляет свой текст, обработчик сохраняет его в FSM под
именем user_text:

    await state.update_data(user_text=message.text)

FSM — это хранилище данных текущего диалога. Исходный текст сохраняется там,
а не внутри кнопки и не в callback_data. Поэтому callback_data остаётся короткой:
в ней только название действия и ключ стиля, а длинный текст в ней не нужен.

4. Что означает split(':')
-------------------------

При нажатии обработчик сначала проверяет начало callback_data:

    F.data.startswith("shrift:")

Это условие направляет сюда нажатия только от кнопок со шрифтами. Кнопки
«На главную» и «Новый текст» имеют другие callback_data и сюда не попадают.

Дальше выполняется:

    key = callback.data.split(":")[1]

Метод split(":") делит строку по двоеточию. Например:

    "shrift:bold".split(":")

даёт список из двух частей:

    ["shrift", "bold"]

Индексы списка начинаются с нуля:

- [0] — "shrift", название действия;
- [1] — "bold", ключ выбранного стиля.

Поэтому [1] записывается в переменную key. Для callback_data "shrift:italic"
в key попадёт "italic".

5. Как ключ снова находит функцию
---------------------------------

Перед обработкой нажатия исходный текст достаётся из FSM:

    text = data.get("user_text")

Затем ключ используется как индекс словаря:

    shrifts_dict[key]

Если key равен "bold", выражение shrifts_dict[key] вернёт функцию
fancify_text.bold. Скобки вызывают эту функцию и передают ей исходный текст:

    shrifts_dict[key](text)

Это можно прочитать так: «найти в словаре функцию по ключу и применить её
к тексту».

Например, если пользователь отправил "Hello", а нажал кнопку с callback_data
"shrift:bold", цепочка будет такой:

    callback_data:            "shrift:bold"
    после split(":"):         ["shrift", "bold"]
    key:                      "bold"
    shrifts_dict[key]:        fancify_text.bold
    вызов функции:            fancify_text.bold("Hello")
    результат:                жирно оформленный "Hello"

Результат передаётся в edit_text, то есть бот меняет текст сообщения под
клавиатурой. Клавиатура создаётся заново из того же словаря и остаётся доступна.

6. Почему стили не накладываются друг на друга
----------------------------------------------

При каждом нажатии текст снова берётся из FSM: data.get("user_text"). Это
исходный текст пользователя. Бот не берёт предыдущий результат из сообщения.

Поэтому, если сначала выбрать bold, а потом italic, получится курсивный
исходный текст, а не курсив от уже жирного результата.

7. Как добавить новый стиль
--------------------------

Добавьте в shrifts_dict новую пару «уникальный ключ: функция». Например:

    "new_style": fancify_text.newStyle

Клавиатура сама переберёт новую запись и создаст кнопку. Ключ "new_style"
окажется в callback_data "shrift:new_style". После split обработчик получит
тот же ключ и найдёт по нему функцию в словаре.

Важно: ключ должен быть уникальным и не содержать двоеточие, потому что
двоеточие разделяет название действия и ключ в callback_data.

Если user_text отсутствует в FSM, обработчик не сможет преобразовать текст:
он сообщит, что текст не найден, и предложит отправить его заново.
